# 예비자 PPT Export 베타 전략

> 현재 베타에서 검증할 1차 제품 약속: `매주 예배 PPT 준비 시간을 줄여주는 FILE 중심 export 워크플로`

---

## 1. 베타 포지셔닝

- **무엇을 파는가**: 기존 `.pptx` 파일을 버리지 않고 예배 순서대로 합쳐 한 번에 내보내는 도구
- **무엇을 아직 안 파는가**: AI 설교 준비 보조, 찬송가 AUTO, 교독문 AUTO
- **왜 이 웨지인가**: 가장 반복적이고 고통이 큰 작업이 주간 PPT 합본이기 때문

추천 한 줄 설명:

> 예배 준비자가 매주 쓰던 PPT 파일을 그대로 올리고, 성경봉독만 자동으로 넣어 단일 PPT로 내보내는 도구

---

## 2. 1차 타겟 사용자

- **주 사용자**: 실제로 매주 PPT를 만드는 전도사, 간사, 봉사자
- **후순위 이해관계자**: 담임목사, 부교역자, 의사결정자
- **베타 원칙**: 결제 의향보다 반복 사용 여부를 먼저 본다

---

## 3. 베타 성공 기준

- 한 교회에서 최소 **연속 3회** 실제 예배 준비에 사용
- 사용자가 기존 방식 대비 **20분 이상 시간 절약**을 체감
- 사용 후 "다음 주에도 다시 쓰겠다"는 명시적 의사 확보
- 관찰 세션 기준 export 치명 실패율 **10% 미만**

실패 신호:

- 첫 사용 후 바로 기존 작업 방식으로 복귀
- FILE 모드보다 수작업이 더 빠르다고 느낌
- 성경봉독 AUTO보다 파일 첨부·수정이 더 자주 필요함

---

## 4. 베타 운영 방식

- **배포보다 관찰이 우선**: 공개 런칭 전, 가까운 1개 교회에서 깊게 관찰
- **온보딩은 수동 진행**: 개발자가 템플릿과 첫 export를 함께 설정
- **첫 세션은 화면 공유 또는 대면 관찰**
- **세션 직후 인터뷰**: 무엇이 빨랐는지보다 어디서 막혔는지 먼저 기록

사용자에게 미리 알려야 할 제약:

- 일부 PPT는 병합 후 폰트·색상이 원본과 다르게 보일 수 있음
- 미디어가 많은 PPT는 병합 실패 가능성이 있음
- 성경봉독 AUTO는 외부 성경 사이트 의존성이 있음

---

## 5. 관찰 로그 템플릿

아래 필드를 매 사용 세션마다 남긴다.

| 항목 | 예시 |
|---|---|
| 날짜 | 2026-04-20 |
| 교회 | 새벽이슬교회 |
| 사용자 역할 | 전도사 |
| 예배 종류 | 주일예배 |
| 사용한 항목 타입 | HYMN, BIBLE, SERMON |
| 준비 시간 | 기존 45분 / 예비자 18분 |
| 막힌 단계 | 파일 업로드, export 실패, 성경봉독 범위 입력 |
| 우회 방식 | 기존 PPT에서 직접 수정 |
| 가장 좋았던 점 | 파일 합치기 시간이 크게 줄었음 |
| 가장 아쉬운 점 | 병합 후 폰트가 달라짐 |
| 다음 주 재사용 의사 | 예 / 아니오 |
| 다음에 가장 필요한 기능 | 찬송가 AUTO |

---

## 6. 후속 의사결정 기준

- `FILE 중심 사용`이 반복되면: 예배 PPT 워크플로 도구로 더 선명하게 집중
- `성경봉독 AUTO` 재사용이 높으면: 성경 관련 자동화 강화
- `AI 설교 준비` 요청이 사용자의 자발적 피드백으로 반복되면: Phase 2 우선순위 상향
- `테마/폰트 충돌`이 베타에서 자주 나타나면: Aspose.Slides 검토
